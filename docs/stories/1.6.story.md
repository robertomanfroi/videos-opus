# Story 1.6 — Vídeos Opus no Mac (Claude e Codex)

**Status:** InProgress
**Épico:** Skill videos-opus para alunas leigas (pacote único, instala uma vez)
**Data:** 2026-10-19
**Origem:** pedido do Roberto — alunas de Mac não conseguem usar a skill (o card da MIRA diz "só Windows").

## Contexto

O pacote leva os programas dentro (FFmpeg, Node, whisper.cpp, kit de estilos com node_modules nativos), todos
compilados para Windows, e os instaladores são `.cmd`. O código dos scripts já tem caminhos de reserva fora do
Windows; o que falta é: binários de macOS, navegador (Chrome no lugar do Edge), aceleração da Apple, instalador
por Terminal e os textos do SKILL.md.

Decisões (Roberto, 2026-10-19): versão **completa** (tudo o que o Windows faz) e instalador para **Claude e Codex**.
Sem Mac físico: compilação e teste de ponta a ponta nos runners macOS do GitHub Actions (repo público).
Instalação pelo Terminal (`curl … | bash`): arquivo baixado pelo curl não recebe a marca de quarentena, então o
Gatekeeper não barra e não precisa de conta Apple Developer.

## Critérios de aceite

1. [x] Scripts portáteis: navegador no Mac (Chrome, Edge, Brave, Chromium; sem nenhum, baixa o Chrome headless
       na instalação), pastas de dados no Mac, `h264_videotoolbox`, CoreML no recorte de pessoa, `open` no lugar
       do PowerShell. Windows segue igual (testes e diagnóstico verdes no Windows).
2. [x] SKILL.md (Claude e Codex) e skills do kit dizem como rodar o Node no Mac.
3. [x] Binários de Mac (Apple Silicon e Intel) gerados no GitHub Actions: node, ffmpeg/ffprobe, whisper-cli e
       node_modules do kit.
4. [x] (feito por `mac/empacotar-mac.sh`, no GitHub Actions) `empacotar.sh` gera `videos-opus-mac-arm64.zip` e `videos-opus-mac-x64.zip`.
5. [x] `instalar-mac.sh` e `instalar-mac-codex.sh`: detectam o chip, conferem espaço, baixam, trocam a versão com
       segurança e rodam o diagnóstico.
6. [x] Teste de ponta a ponta nos Macs do GitHub (arm64 e Intel), instalando pelo instalador: diagnóstico, corte +
       legenda, edição viral, vídeo animado e um estilo do kit.
       → rodada 39305594021: arm64 e Intel verdes; sem nenhum navegador, o instalador baixou o Chrome de gravação e o
         vídeo animado e o render do kit saíram com ele; recorte da pessoa pelo CoreML nos dois.
7. [ ] Release publicada com os zips de Mac e os instaladores; README, guia e card da MIRA com o passo do Mac.

## Dev Agent Record

**Correções do QA (2026-10-19):**
- 1: o instalador testa o navegador de verdade; se o Chrome/Edge do Mac não abrir (ou não existir), baixa o Chrome
  de gravação e testa de novo. Causa no runner: um segundo Chrome fora de /Applications, que fechava ao abrir.
- 2: o teste esconde os navegadores também em ~/Applications, registra quais a skill enxerga e renderiza o kit
  (HyperFrames) usando só o Chrome de gravação.
- 3: corpo do `instalar-mac.sh` dentro de `main()`.
- 4: Codex no Mac lê `~/.codex/skills` (docs da OpenAI) e roda no app do Codex ou no do ChatGPT; a mensagem final
  cita os dois e pede para reabrir o app. Ainda sem teste num Mac real.
- 5: FFmpeg conferido como 9.0.2 (o mesmo do Windows; build novo para a compilação) e Node conferido pelo SHASUMS256.
- 6: os zips só são anexados por um job que depende dos dois Macs aprovados, junto com o `instalar-mac.sh`.
  Limite que fica: entre publicar a release e o anexo (~20 min) o comando do Mac não acha os zips.
- 7: zip novo do Windows (`empacotar.sh`) instalado pelo `instalar.cmd` com zip local: PRONTO, diagnóstico verde,
  vídeo animado gravado. O CA 5 cita `instalar-mac-codex.sh`; foi feito como `instalar-mac.sh codex` (um arquivo só).
- 8: resolvido junto com o 1 (o instalador não monta mais código JS com o caminho).
- 9: actions em checkout@v5, setup-node@v5, upload/download-artifact@v5.
